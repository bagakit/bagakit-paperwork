# 写作技巧总纲（v12）

这版总纲承接 `v11`，重点解决三件事：术语统一、主稿与执行信息分层、指标口径可复盘。它保持“段落主导、结构清晰、执行可落地”的基线，不以牺牲可执行性换取表面流畅。

## 1. 迭代前置动作（基线门禁）

每次新增版本前，先读上一版 `techniques.md`、gap 分析和最新审计。  
先确认哪些能力必须保留，再决定本轮新增技巧。  
这一步同时约束正文、技巧文档和 skill 规范文档。

## 2. 术语治理

术语要在首屏锁定并保持一致。  
如果正文使用“专家论坛”，就不在同一版本混用“专家评审系统”等并列称谓。  
术语统一直接影响检索、交接和跨文档映射质量。

## 3. 主稿与执行信息分层

主稿回答“为什么”，执行附录回答“怎么做”。  
字段级门禁、评分公式、失败处理等高密度规范信息，优先放附录或执行版，避免打断对外阅读节奏。  
这不是信息删减，而是信息分层。

## 4. 结构与扫描策略

保持 `H2` 3~5 个、每个 `H2` 配 `H3` 锚点。  
`H3` 的作用是帮助读者在 30 秒内定位“问题、机制、信号”，而不是增加标题数量。  
段落负责因果和权衡，列表与表格负责并列核对。

## 5. 论证顺序与证据链

章节开头先给判断，段落内部先证据与机制，段尾落动作和验收。  
证据链推荐固定为：`现象 -> 机制 -> 证据 -> 信号 -> 行动`。  
缺任何环节时，必须说明替代证据或风险边界。

## 6. 可执行性表达（防回退）

可执行性必须保留字段级锚点，常见最小集合：

| 字段 | 要求 | 失败处理 |
|------|------|----------|
| `discussion_clear` | `true` 后才可交接 | 返回论坛 |
| `user_review_status` | `approved/changes_requested` | 维持待办 |
| `claim_validation` | `pass/fail` + 证据 | 标记未验证 |
| `tool_usability` | `pass/fail` + 复现路径 | 标记不可用 |
| `handoff_destination` | 可定位路径 | 视为未交接 |

## 7. 指标口径设计

指标必须附采样口径，否则只能口头比较。  
至少定义四个参数：采样对象、样本量、统计周期、通过阈值。  
没有口径的指标，不进入版本评估结论。

## 8. 图示策略

架构图说明依赖关系，流程图说明回退条件，循环图说明长期迭代。  
图后必须有一句解释“这张图解决了什么判断问题”。  
图的目标是降低理解成本，而不是增加展示元素。

## 9. 去 AI 味的持续策略

去 AI 味的核心不是“口语化”，而是“减少模板痕迹并增加责任主体”。  
具体做法包括：减少口号句、减少抽象名词堆叠、减少过度列表，增加场景细节、动作对象和验收语句。

- [x] 主稿与执行字段分层（字段表下沉附录）
- [x] 指标补采样口径（对象/样本量/周期/阈值）
- [x] 正文描述适度扩写，避免“信息够但细节薄”
