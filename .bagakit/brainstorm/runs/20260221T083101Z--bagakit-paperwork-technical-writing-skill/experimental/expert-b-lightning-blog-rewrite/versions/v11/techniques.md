# 写作技巧总纲（v11）

这份总纲服务一个明确目标：把讨论转成可执行、可回溯、可交接的文档。它不是“写得像文章”的装饰规范，而是“写完能被团队使用”的生产规范。

## 1. 版本基线规则（强制）

每次出新版本前，先读上一个版本的技巧文档与 gap 分析，再读最新审计。先继承，再创新。这样做的目的很直接：避免新技巧带来旧能力退化。

这一规则同时适用于三类文档：
- 正文（面向读者）
- 技巧文档（面向作者）
- skill 规范文档（面向执行系统）

如果新版本在某项能力上回退，必须在 gap 分析里写清原因和补偿策略，不能“默认回退”。

## 2. 受众与任务定义

开篇先回答两个问题：这篇写给谁，读完要完成什么动作。  
没有这两个锚点，后续结构再完整，也会退化成“观点展示”而不是“任务文档”。

受众描述要具体到场景。例如，不写“给开发者看”，而写“给要把讨论结果变成计划并交接给下一位执行者的人看”。

## 3. 用词与句法

用词的核心原则是“动作优先于形容”。  
与其写“需要进一步优化机制”，不如写“补充验收字段，并在 handoff 前回填 user_review_status”。

句法上采用“判断句 + 机制句 + 约束句”的三段式。判断句负责立论，机制句负责解释，约束句负责落地。  
被动语态和无主语句要克制使用，避免责任主体消失。

## 4. 段落与分点

正文以段落为主，分点为辅。  
段落用于因果、权衡和反例；分点只用于并列且可单条验收的信息。

可以用一个简单判断法：如果读者需要理解“为什么”，就写段落；如果读者需要快速核对“是否满足”，就写分点或表格。

## 5. 结构设计与扫描效率

推荐结构是：`H1` 一个主命题，`H2` 三到五个主问题，`H3` 负责展开“判断 -> 机制 -> 信号”。  
这样既能支持顺读，也能支持 30 秒扫读。

标题应尽量可独立理解。抽象标题（如“机制设计”“能力提升”）会增加读者翻译成本。  
更好的写法是问题句或动作句，例如“这次讨论为什么总在交接时失真”。

## 6. 论证一致性与证据链

为避免“先判断还是先证据”的伪冲突，可以分层处理：章节导航先给判断，段落论证先给证据和机制，段尾再给局部结论与动作。

稳定的证据链通常是：`现象 -> 机制 -> 最小实验/案例 -> 验证信号 -> 行动`。  
缺任何一环都可以写，但必须说明缺失原因和替代证据。

## 7. 可执行性表达（防回退重点）

技术文章只要涉及流程建议，就需要字段级约束。  
这类约束不必很多，但必须明确。典型字段包括：

| 字段 | 最低要求 | 失败处理 |
|------|----------|----------|
| `discussion_clear` | `true` 才能进入 handoff | 返回论坛继续收敛 |
| `user_review_status` | 仅允许 `approved/changes_requested` | 不得进入完成态 |
| `evidence_map` | 关键结论必须映射到证据 | 标记为待补证据 |
| `handoff_destination` | 必须有可定位去向 | 视为未交接 |

可读性优化不能以牺牲这些硬信号为代价。若必须弱化展示，应改为“发布版折叠展示”，而不是删除约束。

## 8. 反例压力与风险控制

每个关键判断都应有至少一个反例或失败路径。  
反例不是为了“挑刺”，而是为了定义边界：这套方法在哪些条件下失效，失效时如何回退。

如果一段论证没有反例，通常意味着它还停留在宣讲层，而非工程层。

## 9. 图示策略

图用于承载结构信息，正文用于解释设计理由。两者分工不清时，图会变成装饰。

推荐三类图：
- 架构图：解释模块依赖关系
- 流程图：解释步骤与回退条件
- 循环图：解释长期运行与迭代机制

每张图后都应有一句“这张图解决了什么判断问题”。

## 10. 发布版与执行版双投影

一份主稿可以同时支持对外发布和对内执行。  
发布版保留问题场景、案例和核心结论；执行版补充门禁字段、评分规则、交接路径。

关键原则不是“写两篇”，而是“同源表达”。一旦分叉维护，语义漂移几乎不可避免。

## 11. 去 AI 味策略（基于检索与实作）

AI 味通常来自三个来源：风格同质化、抽象词过密、列表过载。  
对应动作是：降低口号句密度、增加具体主体与动作、恢复自然段叙述比例。

去 AI 味不等于去结构。最理想状态是：结构清楚、语气自然、证据可复核。

## 12. 发布前质检清单

- [ ] 开篇是否写清受众与任务
- [ ] 是否保留字段级执行约束
- [ ] 是否存在至少一处反例闭环
- [ ] 标题是否支持快速扫描
- [ ] 图示是否承担结构信息而非重复文字
- [ ] 可读性提升是否伴随可执行性保持或提升
