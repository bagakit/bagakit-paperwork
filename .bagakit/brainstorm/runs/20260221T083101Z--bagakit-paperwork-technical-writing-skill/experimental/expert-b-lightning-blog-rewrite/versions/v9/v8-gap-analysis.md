# v8 Gap Analysis (for v9 Rewrite)

## 结论先行

`v8` 已经具备较好的读者友好度和执行意识，但仍存在“门禁感强、系统感足、刊载张力不足”的问题。`v9` 的目标不是推翻，而是把这些缺口变成可操作改写动作。

## 对照清单

| 维度 | v8 观察 | 影响 | v9 处理动作 |
|------|---------|------|-------------|
| 读者契约 | 开篇有受众说明，但任务收益不够聚焦 | 读者知道“写给谁”，但不够清楚“读完能做什么” | 在引言补“目标只有一个”的任务句，并在结尾回扣 |
| 论证一致性 | 已提出双层顺序，但操作感偏弱 | 容易被读者当作术语解释而非写作规则 | 在 H2-2 用“导航层/论证层/执行层”三层写法落地 |
| 反例压力 | 有失败样本，但反例闭环不足 | 结论稳健性不够，像单向宣讲 | 在 H2-1 加“反例压力测试”并给修复逻辑 |
| 信息架构 | 主体结构清晰，但图示缺席 | 抽象关系需要读者脑补 | 增加架构图、流程图、循环图并附解读句 |
| 可执行性 | 有门禁字段与评分公式 | 机制在文中分散，执行路径不够一眼可见 | 在 H2-3 用流程图收拢“回路式门禁” |
| 发布适配 | 已有对外/对内表格 | 仍偏概念，缺“共用主稿”的方法论 | 强化“双投影”与“单主稿”策略 |
| 验收信号 | 有三项指标 | 指标与系统目标关联可更直接 | 在 H2-4 将指标绑定“接口层是否生效” |

## v9 验收标准

- [x] 保持 5 个 H2，避免平铺扩散
- [x] 至少 1 个反例压力段
- [x] 至少 3 张图（架构/流程/循环）且图后有解读句
- [x] 双层论证顺序有明确操作表达
- [x] 发布适配和执行适配可共用同一主稿
