# 技术写作优化经验沉淀（v1-v12）

这份文档不是“过程回忆录”，而是下一轮优化可以直接复用的执行手册。  
我们在 v1-v12 的核心结论很明确：真正决定质量上限的，不是单轮语言润色，而是“问题定义、证据绑定、评测门禁、交接结构”是否稳定协同。

## 1. 目标定义：从“写得更顺”升级到“写完可执行”

单纯提升可读性，往往会带来隐性回退：段落更自然，但执行约束被稀释；叙事更流畅，但证据锚点变少。  
因此本实验把目标拆成两个同时成立的条件：

- 对外可发布：叙事完整、术语稳定、读者可快速抓主线。
- 对内可执行：字段级门禁明确、回退条件可触发、handoff 去向可定位。

只有双条件同时成立，才算“完成优化”，否则只是“单边改善”。

## 2. 演进主线：四段式能力抬升

| 阶段 | 版本 | 主能力增量 | 典型风险 | 修复策略 |
|------|------|------------|----------|----------|
| 基线建立 | v1-v3 | 从初稿重写到读者触发型结构 | 结构可读但约束不稳 | 引入上一版继承清单与 gap 回填 |
| 结构成型 | v4-v7 | outline-first、层级金字塔、方法合成 | 结构增强后易变模板腔 | 保留段落叙事主导，控制口号密度 |
| 审计拉齐 | v8-v10 | 融合审计视角与可执行性表达 | “自然表达”挤压硬门禁字段 | 显式恢复字段级约束与证据映射 |
| 双投影稳定 | v11-v12 | 发布主稿/执行附录分层，术语统一，采样口径明确 | 文档边界不清导致信息混杂 | 发布叙事与执行规范分层维护 |

## 3. 被验证有效的优化机制

### 3.1 版本基线门禁（先继承，再创新）

每次写新版本前，必须先读取上一版 `techniques`、`gap-analysis` 和最新审计结论，生成三栏清单：

- 保留项：不可退化能力；
- 新增项：本轮新增策略；
- 收紧项：必须从“建议”升级为“约束”的部分。

这一步的作用是阻断“局部变好、全局回退”。

### 3.2 证据先行的论证顺序

章节层面先给判断，段落层面先给证据与机制，再落动作。  
这样既能保留阅读速度，又不牺牲复核能力。

### 3.3 同源双稿策略

- 主稿回答“为什么”；
- 执行附录回答“怎么做、谁验收、失败后如何回退”。

这不是多写一份文档，而是把不同读者的需求拆开，避免互相干扰。

### 3.4 术语与锚点治理

术语必须统一到一个主称谓（例如“专家论坛”），关键结论必须能定位到具体证据位置。  
术语漂移和锚点缺失，是交接失真的两个高频起点。

## 4. 评测体系：三层 Gate，不混用职责

我们采用三层 gate，并明确偏好 `Program Warning for Agent + Agent Gate`：

### 4.1 Program Hard Gate（少而硬）

只覆盖确定性约束：

- 结构与 schema 完整性；
- standalone 约束；
- 反耦合约束（禁止强绑定外部流程）；
- 必要的文件与路径完整性。

Hard gate 的原则是“可机器确定且必须阻断”。

### 4.2 Program Warning for Agent（信号层）

处理启发式问题，不直接阻断：

- 触发描述是否清晰；
- 文档结构是否便于扫描；
- 可读性/术语一致性风险提示。

Warning 的价值是把机器信号交给下一层判断，而不是替代判断。

### 4.3 Agent Gate（决策层）

用评测 rubric 产出最终结论（`approve` / `revise`），并强制：

- `P1/P2/P3` 严重度分级；
- `file + line` 证据锚点；
- 分项评分与阈值判定；
- 明确下一步修订动作。

禁止事项：任何会引入 mandatory coupling 的“主观质量硬校验”都不能进入 hard gate。

## 5. 高发回退模式与修复动作

| 回退模式 | 触发信号 | 修复动作 |
|----------|----------|----------|
| 元数据泄漏到发布稿 | 读者看到版本/思维模型等内部字段 | 将内部过程信息移至执行附录或版本文档 |
| 可读性提升但可执行性下降 | 约束从字段规则变成叙述性建议 | 恢复字段级门禁与失败处理路径 |
| 结构“顺”但不可扫读 | 只有长段，缺少 H3 锚点 | 重建 30 秒抓要点的层级锚点 |
| 术语漂移 | 同一概念多称谓并存 | 锁定主术语，建立替换清单 |
| 指标不可复盘 | 指标有名称但无采样口径 | 补齐样本量、统计周期、通过阈值 |

## 7. 下一轮可直接执行的流程

1. 读取上一版三件套：`techniques`、`gap-analysis`、审计结论。
2. 产出“保留项/新增项/收紧项”清单。
3. 先写主稿骨架，再补执行附录约束。
4. 跑 `Program Hard Gate`，清零阻断错误。
5. 汇总 `Program Warning for Agent` 进入评测输入。
6. 跑 `Agent Gate`，输出 P 级问题、评分、结论。
7. 仅当“无 P1 + 阈值达标 + 无未解释回退”时进入发布。

## 8. 结语

这轮优化最重要的产出，不是某一版文稿，而是一套可复用的决策秩序：  
先定义边界，再组织证据，再分层评测，最后交接执行。  
只要这套秩序不丢，下一轮质量可以持续抬升，而不是靠临场发挥。
