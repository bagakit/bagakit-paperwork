# Insight Interview Loop

当用户的材料已经足够多，但真正的判断、主轴和文风还没有完全显性化时，直接写正文通常会偏平。

这时更好的做法，不是继续补材料，而是先跑一轮“洞察与追问”。

## 这套机制解决什么问题

它主要解决三类问题：

1. **用户想得比草稿深，但没完全说出来**
2. **材料很多，但作者真正想押注的命题还没压实**
3. **需要写得像用户本人，而不是像一个成熟编辑在代写**

## 核心思想

不是先让用户自己从零回答一堆问题。

而是：

1. agent 先基于材料分析一轮
2. 给出一组有默认答案的高质量问题
3. 用户不需要答完，只需要改掉最关键的部分
4. agent 再从这些回答里，提炼更深的命题、强句、风格边界和更高阶的因果链

用户的回答不必完整。只要足够真实，就足够有价值。

## 为什么它有效

### 1. 它降低了用户表达门槛

如果一开始就让用户从零回答，很多高价值判断其实不会自然写出来。

而有默认答案时，用户更容易：

- 直接删
- 直接改
- 只补最关键的一句

这种“局部改写”往往比从零回答更能暴露真实判断和真实风格。

### 2. 它能同时拿到“信息”和“口吻”

用户在改默认答案时，传递的不只是观点内容，还会传递：

- 哪些词不能用
- 哪些层级必须再抬高
- 哪些地方必须更朴实
- 哪些地方允许强烈的“我”

这类信息很难靠普通访谈直接问出来。

### 3. 它给 agent 提供了高质量推演材料

当用户只改了少数几条，但改得很重，agent 反而更容易看出来：

- 用户真正想写的不是表层主题，而是更深一层的东西
- 哪些问题已经被提前回答了
- 哪些未回答的问题，其实边际价值已经不高

## 标准工作流

### Phase 1：Agent 预分析

先由 agent 基于已有材料做一轮预分析。

输出应包括：

1. 分组问题
   - 总判断
   - 体系沉淀
   - 共性经验
   - 正在做什么
2. 每个问题的默认答案
3. 为什么暂时这样判断
4. 可直接带回正文的候选强句

这一步的目标不是替用户回答完，而是先把问题空间压成一个高质量可编辑件。

### Phase 2：用户部分回答

用户不需要答完所有问题。

真正高价值的不是“覆盖率”，而是这几类信息：

- 用户真正认同什么
- 用户最想反对什么
- 用户觉得哪些地方写浅了
- 用户自己的世界观如何比默认答案更深
- 用户自然会怎么说

如果用户只是把某些默认答案改得很重，已经足够。

### Phase 3：Agent 回收强信号

用户回答后，agent 需要做三件事：

1. **提炼世界观**
   - 用户真正想讲的是什么
   - 主稿的真正内核是什么
2. **提炼强句**
   - 哪些句子已经足够强，可以直接带回正文
3. **提炼风格边界**
   - 哪些说法绝对不能再用
   - 哪些说法是用户本人会自然说出来的

### Phase 4：最强大脑式深推

这一步不是继续总结材料，而是基于用户已给出的回答，再往深处推一层：

- 这组判断背后的更高命题是什么
- 它还隐含了哪些因果关系
- 哪些问题其实已经被提前回答，所以不必继续问
- 这篇文章真正的重心是不是已经变了

这里的目标不是替用户发明新观点，而是把用户已经露出来但还没完全压实的东西推到前台。

### Phase 5：回写主稿

只有在前四步完成后，才回到正式文稿。

这时正文要吸收的，不只是信息点，而是：

- 更深的主轴
- 更准的因果链
- 更像用户本人的句子
- 更明确的风格禁区

## 交付物建议

一次完整的洞察问答环，至少可以产出三层东西：

1. `洞察与追问.md`
   - 问题 + 默认答案 + 追问
2. `强句回收.md` 或正文内的强句区
   - 用户已说出的高价值句子
3. `深推记录.md` 或并入 evolve log
   - agent 基于用户回答继续推出来的更高命题

## 适用边界

适合：

- 用户明显有自己的判断，但草稿还写不出来
- 需要把“总结稿”抬成“本人会发的文章”
- 需要同时吸收用户观点和用户文风

不适合：

- 事实信息还远远不够
- 用户只是要快速润色，不想额外投入回答
- 纯公告、纯工具文、纯格式化文稿

## 和普通问答的区别

它不是一个信息收集问卷。

它更像一个写作上的“二次启动程序”：

- agent 先把问题空间压出来
- 用户用部分回答注入真实判断和真实口吻
- agent 再把这些高信号输入回收成更深的正文主轴

## 典型失败模式

1. 问题太多，但默认答案太弱
   - 用户只会嫌烦，不会愿意改
2. 用户只答了一部分，agent却把未回答部分也当成用户立场
3. agent 只回收信息点，没有回收文风和强句
4. agent 继续写成材料总结，没有真正吸收用户已经露出来的世界观

## 进化方向

这套机制还可以继续进化：

1. 给问题增加标签
   - `世界观 / 风格 / 边界 / 强句 / 组织动作`
2. 给用户回答增加高权重标记
   - 例如“用户重写”“用户只补一句但改得很重”
3. 建立“可带回正文的强句池”
4. 建立“用户风格禁区池”

## 准出标准

如果要把这套机制作为 skill 的稳定能力，至少要满足：

1. agent 先做预分析，而不是把空问卷丢给用户
2. 用户可以部分回答，不要求完整作答
3. 回收阶段不仅提炼信息，也提炼风格和强句
4. agent 会基于用户回答继续深推，而不是止步于复述
5. 最终能真实提升正文的深度、意图对齐度和风格贴合度
